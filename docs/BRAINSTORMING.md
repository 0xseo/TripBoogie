# 브레인스토밍

0.3.0에 포함한 일정 세부 탭이다. 전용 운영 DB 마이그레이션을 적용했으며, 웹 API와 Android 빌드 31이 같은 저장·권한 검사를 사용한다.

## 화면과 범위

일정의 `지도 / 한눈에 보기 / 브레인스토밍` 중 브레인스토밍을 선택한다. 문서 목록에서 스프레드시트 또는 그림판을 만들고, 미리보기를 누르면 전체 화면 편집기로 연다. 편집기 위의 문서 선택창으로 두 종류의 문서를 전환한다.

- 스프레드시트: 셀 더블클릭·Enter·F2로 직접 입력/수정, 범위 선택(PC 드래그·Shift, 모바일 여러 셀 선택 버튼), 탭/줄바꿈으로 구분한 복사·붙여넣기, 글자/배경색·굵게·정렬, 행·열 추가/삽입/삭제와 크기 조절. 셀 안 입력창과 상단 입력창의 내용을 공유한다. Enter/Tab/다른 셀 선택으로 저장하고 Esc로 취소하며 Alt+Enter로 줄을 바꾼다. 머리글 경계를 드래그해 크기를 조절하고, 위쪽 열 머리글·왼쪽 행 번호에서 삽입한다. 두 손가락으로 표만 확대·축소한다. 표시 영역의 행·열만 렌더링한다.
- 그림판: 펜, 크기를 조절하는 부분 지우개, 손 도구로 화면 이동, 선분·화살표·사각형·원·글씨. 선택 도구의 박스 드래그로 여러 요소를 선택해 함께 이동/삭제하고, 단일 도형 모서리로 크기를 조절한다. 지우개에서 마우스 올리기/오른쪽 클릭/길게 누르기로 영역 삭제·개체 삭제를 선택하며, 크기 조절 중 실제 굵기를 미리 본다. 글씨 수정과 부분 지우기 상태를 유지하는 이동을 지원한다. 두 손가락 이동·핀치 확대, 휠 이동, Ctrl/Command+휠 확대, 확대/축소/전체 맞춤 버튼.
- 문서: 이름 변경, 휴지통, 복원, 확인 후 영구 삭제. 내용 미리보기와 커스텀 문서 전환 메뉴, 여행 복사/백업에 포함.
- 개인 실행 취소/다시 실행: 최근 100개 작업. 문서 전환/목록 복귀 때 유지하며 전체 새로고침 이후의 영구 버전 기록은 제공하지 않는다. 다른 사람의 최신 변경을 덮어쓰는 실행 취소는 거절한다.

수식 계산, XLSX 파일 호환, 셀 병합, 정렬/필터, 고급 차트, 영구 버전 기록은 첫 범위에 포함하지 않는다. 행·열은 필요에 따라 확장하며 실제 저장 한도를 둔다.

## 저장·동기화

새 테이블은 두 개다. 기존 일정·예약·경비·요약표 테이블의 구조는 변경하지 않는다.

| 테이블 | 용도 |
| --- | --- |
| `trip_brain_documents` | 여행, 문서 종류/이름, 셀·그림 요소 맵, 미리보기, 문서/메타데이터 버전, 휴지통 상태 |
| `trip_brain_changes` | 요청 ID별 변경 기록. 중복 저장 방지와 연결 복귀 시 증분 조회 |

문서 원본은 기존 `workspace` 응답에 붙이지 않는다. 브레인스토밍 목록과 개별 문서 API로 따로 읽는다. 셀·그림 요소마다 저장 시점의 stamp를 검사하며, 여러 변경을 한 요청으로 보낼 때는 전체가 성공하거나 취소된다. 행·열은 안정적인 ID 배열로 관리하여 삽입 중에도 다른 셀의 주소가 유지된다.

충돌한 변경은 사용자별 기기 임시 보관소에 남긴다. 동행의 최신 내용을 읽은 뒤 명시적으로 내 변경 적용 또는 내 변경 버리기를 선택한다. 연결 오류는 같은 요청 ID로 재시도하며 권한·용량·검증 오류를 자동으로 반복 전송하지 않는다. 저장에 성공해야 `저장됨`으로 표시한다. 인증 계정이 바뀌면 이전 계정의 저장 세션을 중지한다.

펜과 지우개는 손을 뗐을 때 한 작업으로 저장한다. `realtime.send`가 비공개 여행 채널에 문서 ID만 알리고 클라이언트가 인증된 API에서 증분을 조회한다. 동행 접속/선택 셀 표시는 Presence로 전달한다. 클라이언트는 권위 있는 변경 알림을 보낼 수 없다. 소켓 연결이 불안정할 때는 5초 간격 조회와 온라인/앱 복귀 조회로 보완한다. 그리는 중의 임시 획을 매 프레임 전송하지 않는다.

모든 새 테이블에 멤버십 RLS를 적용하고, 직접 쓰기를 금지한다. 기존 사용자 JWT → 공개 INVOKER RPC → 비공개 인증 dispatcher 경로를 유지한다. 멤버 제거/여행 삭제와 공유 여행 잠금으로 조정하고, 요소 변경은 문서 잠금과 여행 용량 잠금 아래 처리한다. Realtime 수신/Presence 정책도 여행 멤버십을 확인한다. 기존 private 스키마를 Data API에 노출하지 않는다.

## 한도와 백업

- 휴지통 포함 여행당 문서 30개, 문서 원본 4 MiB, 여행 문서 원본 합계 16 MiB.
- 문서당 저장 주소 30,000개(삭제 표식 포함), 그림판의 활성 요소 5,000개.
- 표 최대 20,000행 × 1,000열. 빈 셀은 저장하지 않는다. 셀당 5,000자, 한 번에 1,000항목 편집.
- 한 획은 최대 4,096개 점. 글씨는 2,000자. 펜/지우개 폭 1~80, 글자 크기 12~96.
- 변경 로그는 문서당 최근 512개 요청/8 MiB 범위로 정리한다. 오래된 클라이언트는 전체 문서를 다시 읽는다. 영구 수정 이력 용도가 아니다.
- 전체 JSON 백업 파일은 최대 24 MiB로 읽으며, 기존 여행 가져오기 API 요청은 4 MiB로 유지한다. 문서 원본은 각각 조회해 내보내고, 가져올 때는 1 MiB 이하의 요청으로 나눈다. 문서 ID와 요청 ID가 가져오기 키로 고정되어 응답 유실/재시도 때 중복 문서가 생기지 않는다. 여행 본체 가져오기는 기존 트랜잭션이며, 문서 복원이 중단되면 생성된 여행을 보존하고 같은 가져오기·복사를 다시 시도해 이어간다.
- 문서 휴지통도 전체 여행 백업에 포함된다. 여행 삭제 시 문서와 변경 로그는 외래 키로 함께 삭제된다.

## 적용과 검증

마이그레이션: `supabase/migrations/20261021125303_brainstorming_documents.sql`. Supabase CLI의 `migration new`로 생성했다. 운영 적용은 프로젝트의 기존 `scripts/supabase-apply-migration.mjs` 절차를 사용한다. 2026-10-21 운영 DB 적용 완료. 실제 Postgres 17.11에서 소유자 저장·중복 요청·오래된 버전 거절·열람자 읽기/쓰기 차단·외부인 RLS/RPC 차단을 하나의 트랜잭션으로 확인하고 전부 롤백했다. 기존 여행·레코드·파일·프로필 수와 버전 합계, 보안 advisor 결과는 적용 전후 동일했다.

```sh
node --test app/brainstorm.test.mjs
npm test
npx tsc --noEmit
npm run lint
npm run build -- --webpack
npm run native:build
```

개발 서버의 `/preview/brainstorm`은 로그인 없이 확인하는 합성 데이터 미리보기다. 실제 계정이나 DB에 전송하지 않는다. 같은 브라우저의 두 탭을 열어 저장·충돌·재적용·개인 실행 취소를 확인할 수 있다. 열람자 보기 전환을 제공한다. 운영 빌드에서는 이 경로가 404다.

자동 검증은 실제 PGlite Postgres의 마이그레이션/HTTP API/RPC/RLS, 원자적인 항목 변경, 중복 요청, 삭제·복원·백업, 행 삽입/실행 취소 보호와 Realtime 정책을 검사한다. Realtime 송신 함수와 인증 전송은 테스트 대역이며, PGlite 단일 연결이므로 운영 WebSocket 전달이나 다중 DB 연결의 경합을 검증한 것으로 취급하지 않는다.

브라우저 미리보기에서 두 탭 동기화, 동시 셀 편집의 입력 보존/재적용, 입력/실행 취소/다시 실행, 그림판 전환, 펜과 부분 지우개를 확인한다. 실제 모바일 기기의 멀티터치/키보드와 운영 계정 두 개의 WebSocket 종단 검증은 운영 반영 후 별도로 확인해야 한다.
