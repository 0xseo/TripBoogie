## 현재 앱에서 별도로 발견한 사용 흐름 공백

이 항목들은 현재 코드에서 확인한 공백이며, 원본에도 반드시 같은 기능이 있었다는 주장은 아니다.

1. **개인 여행을 그대로 공유 여행으로 전환하는 기능이 없다.** 개인 여행의 친구 탭은 새 공유 여행 만들기를 열며, JSON 가져오기도 새 개인 여행으로만 복원한다. 따라서 이미 작성한 일정을 친구와 공유하려면 현재 별도 복사 작업이 필요하다. C10.
2. **회원별 정산과 비회원 이름 입력을 구분하지 않는다.** 같은 사람의 이름 표기가 달라지면 정산 참가자 식별에 문제가 생길 수 있으므로 계정/멤버 식별자와 표시 이름을 분리하는 설계가 필요하다. 현재 정산 계산 자체는 없다. C5.
3. **스마트폰·PC 공동 편집 전체 흐름은 추가 검증이 필요하다.** Google·Kakao 로그인 성공 및 생성 후 새로고침 유지에 대한 사용자 확인은 있으나, 이것만으로 초대 수락·권한 회수·동시 수정 충돌의 실제 두 브라우저 검증이 끝난 것은 아니다. C7, C8.

## 데이터 저장 상태 (후속 전환 반영)

- Supabase는 이메일/Google/Kakao 인증과 공유 여행 데이터 저장에 사용한다. 개인 여행은 브라우저 localStorage에 남는다.
- Supabase에 `profiles`, `trips`, `trip_members`, `trip_records`, `trip_invites`와 RLS·트랜잭션 RPC를 적용했다. 기존 로컬 여행 1건과 소유자 멤버십을 이전하고 필드 보존을 확인했다.
- 로컬 미리보기와 배포 앱은 같은 Supabase 프로젝트를 사용한다. D1 원본과 비공개 백업은 보존하며, 앱의 여행 API는 더 이상 D1을 호출하지 않는다.
- 실제 Supabase에서 역할별 권한·초대·수정 검사를 롤백 트랜잭션으로 검증했다. 실제 두 브라우저의 공동 편집 종단 검증은 별도로 남아 있다. 자세한 기록은 [데이터베이스 문서](DATABASE.md)를 참고한다.

## 제안하는 구현 순서

아래 순서는 독립 제품의 사용성과 이미 합의한 요구를 기준으로 한 제안이다. 누락 기능을 모두 구현하거나 원본의 서버·콘텐츠를 복제하라는 의미가 아니다.

1. **공유 데이터 기반 정리:** Supabase 테이블·RLS·기존 데이터 이전은 완료. 실제 두 브라우저 초대/편집/권한 회수 확인, 개인→공유 전환과 여행 삭제를 보완.
2. **지도·장소:** 내장 Google 지도 활성화, 장소 검색/자동완성·선택·저장·일정 연결. 지도 키 설정과 장소 검색 구현은 별도 작업이다.
3. **일정 편집:** 직접 순서 변경, 여러 항목 날짜 이동·삭제, 일정 복사, 거리순 재정렬. 도로 경로/교통별 소요시간은 원본 동작이 이번 증거에서 확정되지 않았으므로 추가 제품 기능으로 범위를 정한다.
4. **경비·정산:** 멤버 식별자 연결, 잔액·송금 계산과 환율, 개인 비용 접근 제어, 메모·사진·결제수단, CSV.
5. **항공·숙소·문서:** 전용 기록과 기간/시간대, 예약 확인서·사진 첨부. 항공편 조회와 실제 예약 판매는 필요에 따라 별도 연결.
6. **여행 중 사용:** 완전한 오프라인 실행/편집과 재연결 처리, 사용자/허가된 가이드 자료 보관. 이후 체크리스트 템플릿·도구함·일정 이미지 내보내기 보완.
